## 3. Rôles, Utilisateurs & permissions
- **Rôles de connexion** : `super_admin`, `gerant`, `comptable`, `chef_caisse`, `serveur`. Définis dans **`src/lib/permissions.ts`** (partagé front/back).
- **Onglet « Utilisateurs »** (`src/components/UsersManager.tsx`) — **visible du super admin uniquement** : créer/modifier/supprimer des membres, choisir le rôle + les onglets visibles, réinitialiser un mot de passe. Endpoints `/api/users` (CRUD, `requireSuperAdminUser` → 403 sinon).
- **Permissions d'onglets personnalisables par utilisateur** : colonne `users.allowed_tabs` (jsonb, null = défaut du rôle). Défauts : super_admin & gérant = **tout** ; comptable = dashboard/finance/rentrées/dépenses ; chef_caisse & serveur = Tables&Additions/Carte/Réservations/Livraisons/Clients/Calendrier.
- **« Le gérant peut tout voir »** : gérant voit finances + salaires (`canAccessSalaries` = super_admin OU gerant).
- **Accès test** : masque les onglets **Paramètres** et **Utilisateurs**.

## 5. Métier (commandes, stocks, personnel, dashboard)
- **Commande (Tables & Additions)** : la **quantité** d'un plat/boisson est **saisissable au clavier** (en plus des +/−).
- **Stocks** : sur un article en **alerte bas**, bouton **« Commander »** qui ouvre une commande fournisseur **pré-remplie**. **Unités** : option **« Autre… »** pour saisir une unité personnalisée (3 sélecteurs : fiche article, ligne de commande, catalogue).
- **Impression addition** : format **80 mm** (imprimantes thermiques) + **logo en noir & blanc** en haut.
- **Fiche employé** : **taux horaire retiré** — on ne gère plus que le **salaire mensuel**.
- **Dashboard** : nouveau **« Bilan des plats vendus »** (jour / 7 derniers jours / mois) ; les **meilleures ventes** affichent la **photo du plat**.
- **Paramètres → Zone de danger** : bouton **« Tout remettre à zéro »** = reset **données financières** (commandes/additions, dépenses dont récurrentes, rentrées) ; confirmation par saisie de « REINITIALISER » ; super_admin uniquement. Endpoint `POST /api/reset-financial`.

## 6. Corrections
- **`express.json` limité à 15 Mo** : le logo/photos en base64 dépassaient les 100 Ko par défaut → erreur « Impossible de modifier les paramètres » (413). Corrigé.
- **Route `PUT /api/users/config`** : elle était interceptée par `PUT /api/users/:id` (`:id="config"` → 500). Corrigé en contraignant `:id` au numérique (`:id(\\d+)`).

## 7. 🚀 Mise en ligne sur Render (EN COURS)
Prêt côté code (voir **`RENDER-DEPLOY.md`**) :
- `server.ts` : port via `process.env.PORT` ; import de `vite` rendu **dynamique** (devDep absente en prod) ; le mode prod sert `dist/` statique.
- `src/db/index.ts` + `drizzle.config.ts` : connexion via **`DATABASE_URL` + SSL** (fallback `SQL_*` en local).
- **`render.yaml`** : **service web seul** (Render limite à 1 base gratuite/compte → la base est **externe**). `.node-version` = 20.19.0.
- **Base de données** : hébergée sur **Neon** (https://neon.tech, projet `restopilote`, Postgres gratuit non-expirant). La connexion string Neon devient la variable **`DATABASE_URL`** du service Render.
- Build Render = `npm install --include=dev && npm run build && npm run db:push` ; Start = `npm run start` ; Health = `/api/health`.
